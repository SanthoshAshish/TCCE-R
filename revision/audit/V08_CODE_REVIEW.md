# v0.8 draft code review (Phase 1 verification, step 3)

Scope: the six modified tracked files (`tccer/config.py`, `network/events.py`, `network/generators.py`, `policies/__init__.py`, `policies/v06.py`, `sim/engine.py`) and the new `tccer/core/predict.py`, `tccer/policies/v08.py`. Method: read every line, traced calls through `engine.simulate -> policy.decide -> MutationPipeline -> SafetyGate`, checked seed streams, and added smoke tests (`tests/test_v08_smoke.py`, 31 tests, all pass). No scientific assumption was changed. **Not reviewed against any specification**, because none exists: `config.py` and `v08.py` cite `docs/PROTOCOL_v0.8.md`, which is not in the repository, and `docs/MATH_SPEC_v0.7.md` covers v0.7 only. The only description of the predictor and objective is the docstring in `predict.py`.

## Changes made during this review (all validation or comment only)
1. `tccer/config.py::__post_init__` now rejects invalid values of the new options (graph family, `ba_m`, `er_p_*`, `obs_noise`, `obs_delay`, shock parameters, `v08_w` format, `cand_k`, `j_*`, `risk_eps`, `pred_horizon_extra`, `v08_front`). Defaults and all valid values are unchanged; 66 existing configs still load. Reason: `non_geometric()` treated **any** family other than `"er"` as Barabasi-Albert, so a typo such as `"ER"` silently produced a different graph.
2. Stale comment in `config.py` (said BA used `er_p_init`; the code uses `ba_m`) corrected.
3. `engine.py`: wall-clock timing moved to an optional side list (previous step).

## Findings (open items need a decision; none was changed)
| # | Area | Finding | Severity | Status |
|---|---|---|---|---|
| 1 | Spec | No protocol or equations document for v0.8 (J, predictor, hazards, risk constraint, hybrid). Behaviour is defined only by code. | High for the manuscript | Open: needs `PROTOCOL_v0.8.md` before any run |
| 2 | Imperfect information | `obs_noise` / `obs_delay` perturb only the E, C, V values the **trigger statistic** reads. They do **not** affect: counterfactual feedback (replays the true exogenous record), the hazard estimator, candidate scoring, the safety gate or lambda2 (all use the true state), and the schedule arms A6/A7 (state-blind). Logged metrics stay true (tested). So this models noisy/delayed *measurement of the stress signals*, not incomplete topology observation or distributed estimation. For `k < obs_delay` the first observation is repeated. | Medium (claims) | Open: describe precisely; do not claim partial-observation robustness |
| 3 | Graph families | ER/BA candidate links are random node pairs (`er_p_pot`), with no radio-range limit; link length is the distance between arbitrary random positions and only breaks ties. The edge budget equals the number of initial links. Initial graphs are made connected by rejection (up to 1000 tries, else `RuntimeError`), so they are conditioned on connectivity. Candidate-link availability therefore differs from the RGG, which confounds "graph family" with "candidate set" in any cross-family comparison. Spatially correlated bursts on ER/BA act on random positions, so they are not topologically meaningful clusters. | Medium | Open: state in the manuscript; consider matching candidate density |
| 4 | Shock | Centre is uniform in the unit square, radius 0.30 by default; the number of links hit varies by seed and can be small or zero. It is logged in `trace.bursts` but looks like a burst in `n_burst_down`. The window may run past the horizon (tested: no error). | Low | Open: report links hit per seed |
| 5 | Predictor, E | `E(a)` is a heuristic: spectral gap of the expected Metropolis matrix, Jensen gap ignored (self-documented). The docstring says it is "validated empirically in the paper"; **no validation exists yet**. | High for any claim | Open: validate against simulated E before use |
| 6 | Predictor, R | Union-bound proxy `(c-1)(1-r)^H + (#bridges)(1-(1-h)^H)`, clipped to 1. Counts links that are configured and not down as up **without regard to setup readiness**, whereas the real live graph excludes pending links. The empirical constraint is `R(a) <= max(risk_eps, R(null))`, which is not a guarantee and relaxes when the network is already at risk. | Medium | Open |
| 7 | Predictor, constants | Hazard priors (h=0.02, r=0.10, weight 20), window 10, rewiring cost `0.25 (+0.75 if a live link is released)`, and horizon `H = d + pred_horizon_extra` are hard-coded or defaulted without justification; J weights (1, 0.5, 0.05, 1) are untuned. The scenario files use p_fail 0.005-0.01. | Medium | Open |
| 8 | Selection | Under a full strict budget every candidate shares the same removed link (`generate_candidates` picks one), so the J-minimisation chooses only among the **added** links, over at most `cand_k` feasible candidates taken from the first 30 lexicographic ranks. `M_*` diagnostics are not logged for predictive picks (NaN). | Low | Open: describe accurately |
| 9 | Deferral | When J does not improve, the attempt counts as a failed attempt, no cooldown is consumed, and the trigger can re-fire every epoch. `v08_pred_only` evaluates 10+ eigendecompositions every eligible epoch (17.8 s for two 24-epoch, 20-node runs in the test suite; cost at n = 80-120 not measured). | Medium (compute) | Open: time before planning scalability runs |
| 10 | Hybrid | Docstring says "first ceil(M/2) rewirings"; the code uses `cfg.v08_front` (default 0, so the default hybrid equals B8, tested). Front-phase mutations go through `TCCERArm._attempt`, so they register counterfactual feedback, update Theta and reset the debt; this is undocumented design behaviour. The front phase uses a simple `k >= 2 * n_mutations` rule and is **not** count-matched to A7's PMF procedure. | Medium | Open: needs a definition |
| 11 | B6 / B7 | B6 bypasses feedback by aliasing methods from other classes (correct as read, fragile). B7 (`v08_rcpr_legacy`) is code-identical to B8 and differs **only** through `cfg.feedback_rule: before_after`; run with a counterfactual config it silently equals B8. | Medium | Open: add a guard or a per-arm config check before running |
| 12 | Ablation coverage | B2-B4 normalise the stress by the weight sum, unlike A4's unnormalised sum, so thresholds need separate calibration. `calibrate_v07.py` and `run_v07.py` know only A0-A7: there are no calibration, frozen configs or runner for B-arms, P1 or H1. There is no dedicated B1 (E-only; closest is A1/A3) or B5 (fixed-threshold debt; closest is A4). | Medium | Open |
| 13 | `v08_w` | Overrides the A4/A5/RCPR weights, but the frozen `kappa_s` was calibrated for 0.5/0.3/0.2, so any sensitivity run must recalibrate. | Low | Open |
| 14 | Numerics | The predictor uses `numpy.linalg.eigvalsh`; BLAS/thread differences of order 1e-15 could flip an argmin tie in J and make v08 arms differ across machines. Same-machine determinism is tested. | Low | Open |
| 15 | Seeds | Random streams are `[seed, 0..6]`: 0 graph, 1 failures, 2 x0, 3 policy, 4 bursts, 5 observation noise (new), 6 shock (new). No collisions; the new streams draw only when their option is on, so defaults leave all older draws untouched (confirmed by the 60-seed replay). | OK | Closed |

## What the tests establish
`tests/test_v08_smoke.py` (31 tests): option validation; defaults inert; ER/BA generators deterministic, connected, with candidate links; non-RGG runs respect the cap, the strict edge budget and a policy-independent failure trace; `make_network` equals the RGG generator by default; shock confined to its window and leaves other random streams unchanged; logged world state is identical under any observation perturbation, the reactive arm reads exactly the delayed value, noise is reproducible and clipped; all 8 `v08_*` arms run, are deterministic, respect the cap/budget and make only rewires; hybrid with `v08_front=0` equals B8; the hybrid front phase acts at epochs 0 and 2 and nowhere else; predictor outputs are in range and J is computed as documented.
They establish wiring and invariants. They do **not** establish that the predictor is accurate, that RCPR or the hybrid performs well, or that the ER/BA settings are sensible.
